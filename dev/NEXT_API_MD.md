# Проверенные факты

Сверено с кодом в предыдущем чате. Всё равно перепроверь перед тем, как писать.

* Стабильных кодов объявлено 28: 10 доменных в `errorMapping`, 12 манифестных в
  `manifestErrorMapping`, 6 остальных (`OK`, `CANCELED`, `DEADLINE_EXCEEDED`,
  `UNAUTHENTICATED`, `PERMISSION_DENIED`, `INTERNAL`).
* Разведение манифестных кодов: форма снапшота → `INVALID_ARGUMENT`, конфликт с
  принятым состоянием → `FAILED_PRECONDITION`.
* Текст ошибки наружу берётся из таблицы, а не из `err.Error()`. Исключение —
  `ManifestValidationError`: у него наружу уходит деталь, потому что тип рождается
  только в чистых функциях над payload вызывающего.
* Порядок проверок в `statusFromError`: доменные сентинелы → контекст → `INTERNAL`.
  Отмена определяется по `ctx.Err()`, а не по тексту ошибки.
* `methodRoles` содержит ровно три метода. Метода нет в таблице — запрещён всем.
* Идентичность берётся из `VerifiedChains[0][0]`, поля `DNSNames` и `URIs`. CN не
  используется. Пустая идентичность отбрасывается дважды: в `config` и в
  `NewAuthorizer`.
* TLS: `MinVersion` 1.3, `RequireAndVerifyClientCert`. Insecure-режима нет.
* Порядок interceptor'ов: request_id → логирование → авторизация. Отказ авторизации
  попадает в лог.
* `x-request-id` из метадаты, потолок 64 байта, иначе генерируется свой.
* Запись лога несёт `method`, `grpc_code`, `error_code`, `duration_ms`,
  `request_id`, `peer_identity`.
* Ответ `GetCustomerAccessLinks` несёт метадату `cache-control: no-store`.
* `ApplyCustomerAccessResponse` пустой. Он же возвращается на устаревшую команду:
  снаружи принятие и идемпотентный no-op неразличимы.
* Состояния ссылки: `PENDING`, `READY`, `BLOCKED`, `FAILED`. Причины блокировки:

# КАК ПИСАТЬ

Четыре версии текста были забракованы. Три раза за форму, один раз за то, что
документ не помогал разобраться в коде. Обе стороны важны.

## Положительное требование

Документация ведёт по коду. Называй файлы, функции, запросы, номера строк. Читатель
должен уметь дойти от абзаца до места в исходнике.

Забракованная версия `ARCHITECTURE.md` состояла из утверждений о свойствах:
«порядок блокировок нормативен», «инвариант держится структурно», «домен
детерминирован». Всё верно, всё взято из шапок пакетов, и раздел про пути не
называл ни одной функции. Принятая версия на те же темы даёт трассировку: 32 файла
и 126 имён функций и запросов в code-span.

Обоснования решений НЕ переносить. Они живут в комментариях к коду, там их
подробно и хорошо. Документация сообщает, что происходит.

## Признаки нейрослопа

* **Одинаковая форма у повторяющихся блоков.** Пятнадцать таблиц с приклеенным
  абзацем одного устройства читаются как сгенерированное, даже когда факты верны.
* **Синонимы вместо термина.** Манифест нельзя называть «снимком» ради
  разнообразия. Один предмет — одно слово во всём документе.
* **«не X, а Y».** Только если ловит конкретное неверное прочтение. В README было
  15, оставлено 3.
* **Жирные зачины абзацев** (`**Access.**`) вместо заголовков `###`.
* **Жирный текст ради нажима** посреди предложения.
* **Оправдание после каждого утверждения** («поэтому», «иначе», «потому что»).
* **Риторические подводки**: «Здесь есть ловушка», «Три вещи стоит знать до того,
  как...». Если нужно сгруппировать — ставь заголовок `###`.

# Правила работы

* Комментарии и документация — ТОЛЬКО на русском. Идентификаторы, hostname'ы,
  имена сервисов и протокольные значения — ASCII. HELP-строки метрик английские.
* **Docker недоступен из песочницы агента** — команды с docker давать мне.
  Зависимости (`go get`, `go mod tidy`) тоже. `go test -short` и
  `go tool sqlc generate` агент запускает сам.
* Пишем по одному файлу. Сначала оглавление на подтверждение, потом текст.
* Коммиты по умолчанию делаю я; если попрошу — делай ты. Каждый коммит обязан
  собираться и проходить тесты. Трейлеры (`Co-Authored-By`) НЕ добавлять. Тела
  коммитов подробные, на русском, с обоснованиями и решениями.
* Следуй фактам кода дословно; расхождения проговаривай, не меняй молча.
* Не переусложняй. Если спрашиваю «нельзя ли проще» — обычно можно.
* Интерактивные git-флаги недоступны. Для разбиения по коммитам: развести по
  непересекающимся файлам и `git add` по путям.
