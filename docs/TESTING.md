# Testing Guide

## Назначение

Документ описывает доступные способы тестирования SpiritVPN в текущем состоянии репозитория.

## Типы тестов в проекте

В репозитории представлены следующие категории тестов:

* unit-тесты для отдельных пакетов;
* тесты обработчиков API;
* тесты репозиториев слоя данных;
* тесты worker-компонентов;
* smoke-сценарий для Xray API.

## Основные команды

### Запуск всех тестов

```bash
go test ./...
```

### Запуск всех тестов с подробным выводом

```bash
go test -v ./...
```

### Запуск тестов конкретного пакета

```bash
go test ./pkg/config -v
```

### Покрытие кода

```bash
make test-coverage
```

### HTML-отчет по покрытию

```bash
make test-coverage-html
```

### Только unit-тесты

```bash
make test-unit
```

### Integration-тесты с PostgreSQL

По умолчанию `go test ./...` не требует внешних сервисов. Для запуска DB-сценариев
поднимите тестовый PostgreSQL и явно включите integration-профиль:

```bash
SPIRITVPN_INTEGRATION_TESTS=1 go test ./internal/payments ./internal/vpn
```

GitHub Actions включает этот профиль автоматически, поскольку test job поднимает
изолированный PostgreSQL service container.

## Пакеты, для которых есть тесты

### `pkg/config`

Покрывает:

* загрузку конфигурации;
* парсинг целочисленных параметров;
* парсинг `time.Duration`;
* значения по умолчанию.

### `pkg/logger`

Покрывает:

* инициализацию логгера;
* работу глобальных функций логирования;
* контекстные логгеры;
* formatter;
* отключение логирования.

### `internal/api/handlers`

Покрывает базовые health check обработчики.

### `internal/database`

Покрывает unit-тестирование репозиториев с использованием мокирования SQL-запросов.

### `internal/workers`

Покрывает базовые сценарии жизненного цикла worker-компонента статистики.

### `internal/vpn`

Содержит unit-тесты VPN/Xray слоя.

## Smoke-проверка Xray API

В каталоге `test/smoke/` расположен отдельный smoke-сценарий `xray_test.go`.

Сценарий выполняет:

1. подключение к Xray API;
2. создание тестового пользователя;
3. запрос статистики;
4. удаление тестового пользователя.

Этот сценарий предназначен для проверки работоспособности интеграции с реальным Xray API и требует подготовленного окружения.

## Зависимости для тестирования

В проекте используются:

* `github.com/stretchr/testify`
* `github.com/DATA-DOG/go-sqlmock`

## Требования к окружению

### Для unit-тестов

Для большинства unit-тестов достаточно установленного Go и зависимостей модуля.

### Для smoke-сценариев

Для smoke-проверок VPN/Xray необходимо:

* доступный Xray API;
* корректная конфигурация Xray;
* возможность подключения по адресу и порту Xray API.

## Рекомендации по запуску

### Во время разработки

Рекомендуется использовать:

```bash
go test ./... -v
```

или запускать тесты по изменяемому пакету.

### Перед коммитом

Рекомендуется выполнить:

```bash
go test ./...
```

### Перед Pull Request

Рекомендуется выполнить:

```bash
go test ./...
make test-coverage
```

## Рекомендации по развитию тестов

1. увеличивать покрытие `internal/api`;
2. расширять тесты `internal/vpn`;
3. покрывать дополнительные сценарии `internal/database`;
4. добавлять integration-тесты для бизнес-потоков;
5. поддерживать актуальность smoke-сценариев для Xray.

## Практические замечания

* unit-тесты должны быть независимыми и воспроизводимыми;
* smoke-тесты следует рассматривать как проверку окружения и интеграции, а не как замену unit-тестам;
* документация по тестированию должна обновляться вместе с появлением новых тестовых сценариев.
