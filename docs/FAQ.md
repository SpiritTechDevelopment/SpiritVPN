# FAQ

## Общие вопросы

### Что такое SpiritVPN?

SpiritVPN — backend VPN-сервиса на Go: VPN Server, API Server, слой работы с базой данных и фоновые worker'ы.

### Какие технологии используются в проекте?

В текущей версии репозитория используются:

* Go
* Xray-core
* VLESS + Reality
* PostgreSQL
* Redis
* Gin
* GORM
* Logrus

### Какие основные компоненты есть в репозитории?

В проект входят:

* `cmd/vpn-server` — запуск VPN-сервера;
* `cmd/api-server` — запуск REST API;
* `internal/database` — модели, подключение и репозитории;
* `internal/vpn` — интеграция с Xray;
* `internal/workers` — фоновые задачи;
* `pkg/logger` — пакет логирования.

## Запуск и разработка

### Как начать разработку?

1. Клонируйте репозиторий
2. Установите зависимости через `go mod download`
3. Создайте `configs/.env` на основе `configs/.env.example`
4. Подготовьте PostgreSQL, Redis и Xray
5. Запустите нужный сервис из каталога `cmd/`

### Какой файл конфигурации используется?

Приложение загружает настройки из `configs/.env`.

### Как запустить API сервер?

```bash
go run cmd/api-server/main.go
```

### Как запустить VPN сервер?

```bash
go run cmd/vpn-server/main.go
```

### Можно ли использовать Docker Compose?

Да. Для локального запуска всех сервисов предусмотрен `docker-compose.yml`.

```bash
docker-compose up -d
```

## API

### Какие API эндпоинты уже доступны?

В текущей версии доступны health check эндпоинты:

* `GET /health`
* `GET /health/advanced`

Также в структуре API предусмотрены заготовки для:

* `POST /api/v1/auth/register`
* `POST /api/v1/auth/login`
* `POST /api/v1/auth/refresh`

На текущем этапе эти auth-эндпоинты возвращают статус `501 Not Implemented`.

### Как добавить новый эндпоинт?

1. Добавьте handler или метод сервера
2. Зарегистрируйте маршрут в `internal/api/server.go`
3. Добавьте тесты
4. Обновите `docs/API.md`

## База данных

### Какая база данных используется?

Для основной модели данных используется PostgreSQL. Для кэширования и служебных сценариев используется Redis.

### Где описаны модели данных?

Все основные модели находятся в `internal/database/models.go`.

### Как выполняются миграции?

В текущей структуре проекта отдельная команда `cmd/migrate` отсутствует. Миграция схемы предполагается через слой `internal/database` и вызов миграции из кода приложения.

### Какие основные сущности есть в БД?

В проекте определены следующие основные модели:

* `User`
* `Subscription`
* `VPNConfig`
* `VPNServer`
* `Payment`
* `TrafficStat`
* `SubscriptionPlan`

## VPN и Xray

### Какой VPN-протокол используется?

Проект ориентирован на Xray с использованием VLESS + Reality.

### Где находится конфигурация Xray?

Базовая конфигурация размещена в `configs/xray.json`.

### Как проверить взаимодействие с Xray API?

В каталоге `test/smoke/` размещен smoke-сценарий для проверки подключения к Xray API и базовых операций с пользователем.

### Какой адрес Xray API используется?

Адрес и порт задаются переменными:

```env
VPN_API_ADDRESS=localhost
VPN_API_PORT=10085
```

### Что проверить, если Xray не запускается?

Рекомендуется проверить:

1. доступность порта VPN;
2. корректность `configs/xray.json`;
3. корректность `VPN_API_ADDRESS` и `VPN_API_PORT`;
4. наличие Xray и доступность его API;
5. логи контейнера или сервиса.

## Логирование

### Какое логирование используется?

В проекте реализован пакет `pkg/logger` на базе `logrus` и `lumberjack`.

### Какие возможности логирования доступны?

* консольный вывод;
* запись в файл;
* отдельный файл ошибок;
* интеграция с Gin;
* интеграция с GORM;
* Telegram-уведомления для критических событий.

### Где находится документация по логгеру?

Подробное описание приведено в `pkg/logger/README.md`.

## Платежи

### Есть ли в проекте настройки для платежной системы?

Да. В конфигурации предусмотрены переменные для YooKassa:

```env
YOOKASSA_SHOP_ID=
YOOKASSA_SECRET_KEY=
```

### Реализован ли платежный flow полностью?

В текущей версии репозитория присутствует конфигурационная и модельная база для платежных сценариев. Полный пользовательский flow оплаты находится в стадии развития.
