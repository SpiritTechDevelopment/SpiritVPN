# Roadmap

## Назначение

Документ фиксирует направления развития SpiritVPN с учетом текущего состояния репозитория.

## Текущее состояние

На текущем этапе в репозитории присутствуют:

* базовая многокомпонентная структура проекта;
* точки входа для API Server, Telegram Bot и VPN Server;
* конфигурационный пакет `pkg/config`;
* пакет структурированного логирования `pkg/logger`;
* слой моделей и репозиториев базы данных;
* health check эндпоинты API;
* интеграция с Xray на уровне внутреннего VPN-слоя;
* worker сбора статистики трафика;
* базовые unit-тесты и smoke-сценарий Xray.

## Приоритеты развития

### Этап 1. Завершение базового MVP

* реализовать бизнес-логику auth-эндпоинтов API;
* завершить базовые пользовательские сценарии Telegram-бота;
* реализовать выдачу VPN-конфигураций пользователю;
* завершить создание и управление VPN-пользователями через Xray API;
* синхронизировать API, bot и database flow.

### Этап 2. Платежные сценарии

* реализовать пользовательский flow оплаты;
* завершить интеграцию YooKassa;
* добавить обработку статусов платежей;
* связать оплату с активацией подписок;
* реализовать обработку продления подписок.

### Этап 3. Управление подписками и конфигурациями

* добавить API для подписок;
* добавить API для VPN-конфигураций;
* реализовать выбор VPN-сервера;
* реализовать обновление и отзыв конфигураций;
* завершить сценарии ограничения по тарифам и устройствам.

### Этап 4. Наблюдаемость и эксплуатация

* расширить логирование компонентов;
* улучшить мониторинг статистики трафика;
* расширить smoke и integration тесты;
* улучшить диагностику Xray и инфраструктурных зависимостей;
* стандартизировать production-конфигурацию.

### Этап 5. Масштабирование

* развить многосерверную архитектуру;
* реализовать управление пулом VPN-серверов;
* добавить логику балансировки и выбора оптимального узла;
* улучшить отказоустойчивость фоновых процессов.

## Технический roadmap

### API

* завершить auth handlers;
* реализовать user endpoints;
* реализовать subscription endpoints;
* реализовать payment endpoints;
* реализовать VPN config endpoints;
* добавить авторизацию и middleware.

### Telegram Bot

* реализовать пользовательские команды;
* реализовать сценарий покупки подписки;
* реализовать сценарий получения конфигурации;
* реализовать сценарий управления подпиской.

### Database

* расширить репозитории;
* покрыть слой данных дополнительными тестами;
* стандартизировать миграционный сценарий;
* подготовить устойчивый seed-процесс для тарифов и служебных данных.

### VPN / Xray

* завершить интеграцию жизненного цикла VPN-пользователя;
* реализовать безопасное обновление конфигураций;
* улучшить сбор и агрегацию статистики;
* расширить диагностику Xray API.

### Logger / Observability

* унифицировать подключение логгера во всех сервисах;
* расширить использование контекстных полей;
* добавить дополнительные тесты для Telegram hook, Gin и GORM интеграций.

## Качество и тестирование

План развития тестирования:

* расширение unit-тестов для `internal/vpn`;
* расширение unit-тестов для `internal/api`;
* расширение unit-тестов для `internal/database`;
* покрытие worker-сценариев;
* развитие smoke-проверок Xray;
* подготовка integration-тестов для связки API + DB + VPN.

## Документация

План по документации:

* поддерживать синхронность README и реальной структуры проекта;
* документировать только реализованные API-контракты;
* обновлять эксплуатационные документы при изменении конфигурации;
* поддерживать единый стиль проектной документации.

## Принцип ведения roadmap

Roadmap должен описывать реальные направления развития проекта и обновляться одновременно с изменением архитектуры, API и эксплуатационных сценариев.
